## 2026-08-19 - Cache Constant Polling and Large Payloads
**Learning:** The dashboard uses a 60-second polling loop (`loadScores()`) to continuously hit the MLB API. This causes extreme redundance when it repeatedly requests boxscores for completed games (`Final` status), fetching the same data ~14 times a minute. It also does a manual refresh loop that fetches the massive season schedule spanning from Opening Day up to Yesterday over and over again without caching.
**Action:** Always intercept aggressive polling loops and apply runtime caching (e.g., `Map`) to finalized endpoints that will no longer change. If an endpoint requires a heavy payload download for a historical date range, use variable caching so the application skips the fetch if the date criteria has not advanced.
